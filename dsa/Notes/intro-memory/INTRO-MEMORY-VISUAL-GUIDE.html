Sheet 01 · the cell

Memory is a lane of numbered bytes

Before any data structure exists, there is one thing: a byte. A byte holds a number from 0 to 255. Memory is a very long row of them, and each one has a number of its own, its address. Click any cell below and follow it.

Write this in the exam

Memory is a linear array of addressable bytes. Each byte has a unique address, and the address of a byte is just an integer. A variable is a named piece of that lane, and its value is stored in the bytes it occupies.

Measured: sizeof(int)=4, sizeof(void*)=8, sizeof(double)=8 on this g++ 15.2.0 / x86-64 build. A pointer is 8 bytes because addresses are 64-bit, which is exactly why a linked node costs more than the number it holds.

A string is the same story with a terminator the compiler adds: char s[] = "DSA" occupies four bytes, 44 53 41 00, and the last one is the 0x00 that ends the string. The bytes above are printed by the capture program, not typed by hand.

Why hexadecimal

One byte needs exactly two hex digits (16 x 16 = 256), so hex is a compact, lossless way to write bytes. Read a real one: 0a means 0 x 16 + 10 = 10. Addresses are written in hex for the same reason, and the 0x prefix is how C++ says "this is hex, not decimal". In the capture above, 0a 00 00 00 are four bytes of one int: value 10, written smallest byte first because x86-64 is little-endian.

Sheet 02 · the address

An address is a number, so address arithmetic is just arithmetic

Because the address of a byte is an integer, you can compute the address of a thing you have never visited. That single idea is the whole reason indexed access is fast. Set a base, a stride and an index below and watch the address fall out of the formula.

SHEET 02 / 10
run output: sections 2, 3
formula: base + i x sizeof(T)

Trap: address arithmetic is type-aware

(char*)p + 1 moves one byte. (int*)p + 1 moves four bytes, because the compiler multiplies by sizeof(int) for you. Writing &a[0] + i and &a[i] are the same address; writing (char*)&a[0] + i is not, and that off-by-stride mistake is a classic exam and viva question.

The three things an address tells you

Which bytethe address itself, e.g. 0x7ffe7c3131b4
Which objectwhich variable or block it belongs to
How far inoffset from that object's base, in bytes

Real offset from the capture: &a[3] is at 0x7ffe7c3131bc, and 0x...bc - 0x...b0 = 12 = 3 x 4. The offset is not a guess, it is the index times the element size.

Sheet 03 · types and alignment

Types decide how many bytes, alignment decides where

A type is a promise about two numbers: how many bytes the value needs, and which byte addresses it is allowed to start on. The hardware loads 4-byte and 8-byte values fastest when they sit on a 4-byte or 8-byte boundary, so the compiler quietly inserts empty bytes to make that true. Move the start offset and watch the ghosts appear.

Two numbers, two jobs

sizeof answers "how far apart are consecutive elements", so it sets the stride. alignof answers "where may this type legally start", so it sets the gaps. Stride and gap together are why a struct is often bigger than the sum of its fields.

The exam answer, in one line

Address of the i-th element of a contiguous block: base + i x sizeof(element). That is one multiplication and one addition, independent of i, so indexed access is O(1). A linked list stores no such arithmetic pattern: the next node's address is inside the current one, so reaching element i is i dependent loads, O(n).

Trap: O(1) is not "one nanosecond"

O(1) counts steps, not seconds. A cache miss on a scattered access can make a constant-time access slower than a sequential scan of the same array: measured here, the same array walked in scattered order ran 12.7x slower per element than the sequential walk (sheet 10). The complexity class tells you how the cost grows, not what it is.

Sheet 05 · the heap

The heap hands out addresses, it does not lay out rows

A contiguous array is one decision made once: here is a block of n x sizeof(T) bytes. A linked structure is a decision made n times: ask the allocator for a node, keep the address it returns, link it from the previous node. Press the button and watch where the nodes actually land.

Notice the pattern: the addresses DO increase evenly here, because this is a fresh heap where nothing has been freed yet. That is exactly the case that goes wrong later: free the middle node, allocate again, and the next node may take that hole. Scattered is the normal state, tidiness is the lucky first minute.

Trap: delete does not empty the memory

delete p tells the allocator that the block is available again. It does not wipe the bytes and it does not change your pointer, so a use after delete still reads plausible garbage. Set the link to nullptr as you unlink a node, and remember that losing the head of a chain leaks every node behind it with no way back.

Why a linked node costs double

A node holding one int occupies 16 bytes of payload but 32 bytes of real memory, spent as 16 payload + 16 allocator overhead and padding. Put the same five ints in an array and you spend 20 bytes total. That is the price of being able to insert anywhere in O(1).

Sheet 06 · stack vs heap

Two ends of the same address space, growing towards each other

Locals are placed by the compiler in a frame on the stack. Dynamic things are placed by the allocator on the heap. Both are in the same address space, at opposite ends, and the gap between them in the capture was 41326 GiB. This is where "static" and "dynamic" in a data-structure question actually come from.

The bug this demo really hit

The first version of the capture program returned the address of a local variable, and -Wall refused it: warning: address of local variable returned. That is not pedantry. A stack address stops being yours the moment the frame returns, while a heap address survives until you free it. Return new, never &local.

Same four fields, two different sizes, one reordering

Rule worth memorising

Each field starts at an offset that is a multiple of its own alignment. The struct's total size is a multiple of the largest field alignment. Reorder fields from largest to smallest and the padding usually disappears: that is why P2 costs 12 and P1 costs 8.

Where this shows up in DSA

The linked-list node in your lab is the canonical case: 4 bytes of data, 4 bytes of padding, 8 bytes of pointer. The pointer is twice the payload, so the "one node" cost of a linked list is never just the data. This is also why arrays win on memory density for the same n values.

Sheet 09 · ADT vs implementation

A stack is a contract, an array is one way to keep it

An abstract data type names the operations and the rules, and says nothing about memory. Two honest implementations of one ADT can have wildly different memory behaviour. Pick an implementation and the cost table tells you what you bought and what you paid.

SHEET 09 / 10
ADT: interface only
implementation: your choice

The ADT is the socket, not the device

Abstract data type

A specification of the values it can hold, the operations it allows, and the rules those operations must obey. The user is allowed to assume the contract and forbidden to assume anything about the storage.

  • Operations: create, insert, delete, search, traverse
  • Invariants: the rules that must stay true after every operation
  • Cost: quoted in terms of n, never in bytes

An ADT hides the layout. That is exactly why the same stack can be an array with a top index, or a chain of nodes, and still be the same stack to its user.

The complexity ladder, with the shape that causes each rung

CostShape that produces itExample here
O(1)address arithmetic, one stridea[i]
O(log n)halving the range each stepbinary search on a sorted array

Big-O counts steps as n grows. It deliberately hides the constant, and the constant is where the memory layout lives: 0.19 vs 2.45 ns is a 12.6x constant, invisible in the notation.

Definitions to write exactly

  • Data structure: a way of organising data in memory so that the required operations can be performed efficiently.
  • Static structure: size and memory fixed at compile time, contiguous block.
  • Dynamic structure: size grows at run time, memory obtained from the heap.
  • Abstract data type: the logical description of the data and operations, with the implementation hidden.

Traps that cost marks in this topic

  1. Saying "the array stores the address of each element". It does not. It stores the elements back to back, and the address is computed from the base plus i x sizeof(T).
  2. Writing "linked list access is O(1) because you have the pointer". You have the pointer to the head.
  3. Confusing sizeof(struct) with the sum of its fields. Padding is real memory.
  4. Calling a heap allocation contiguous. Two consecutive new calls are two unrelated chunks that happen to be adjacent while the heap is fresh.
  5. Treating O(1) as fast. It means the step count does not grow with n, not that the step is cheap.

  1. A byte is described as addressable. What exactly does that mean, in one sentence?

    show answer

    Every byte has its own number (address), and any byte can be read or written independently of the others.

  2. int a[5] starts at 0x7ffe7c3131b0 and sizeof(int)=4. What is the address of a[3], and how many memory accesses does it take?

    show answer

    0x7ffe7c3131b0 + 3 x 4 = 0x7ffe7c3131bc, one multiply and one add, so one step: O(1). The capture printed exactly 0x7ffe7c3131bc.

  3. Why does struct Node {int data; Node* next;} measure 16 bytes and not 12?

    show answer

    Because next is 8 bytes and must start on an 8-byte boundary, so 4 padding bytes sit between data and next. Measured: offsetof(next)=8.

  4. Two structures hold the same five integers. One costs 20 bytes, the other costs 160 bytes as measured here. Which layout is which, and what does the extra memory buy?

    show answer

    The array is 20 bytes (5 x 4). The linked list is 5 nodes x 32 bytes charged, because each 16-byte node costs 32 bytes under this allocator. The extra memory buys O(1) insertion and deletion at a held position, at the cost of O(n) access.

  5. What is the difference between a stack and a heap as memory regions?

    show answer

    The stack is where the compiler places local variables and call frames, it grows downward here, it is freed automatically when the function returns and it is small. The heap is where new and malloc place objects, it grows upward, it lives until you free it and it is large.

  6. Classify: a static array of records, and a binary tree. Give the axis you used.

    show answer

    The array is composite and linear, and static because its size is fixed at compile time. The tree is composite and non-linear (hierarchical), and usually dynamic because nodes are allocated as it grows. The axes are: one value or many, linear or hierarchical, fixed or grown.

  7. A friend says a linked list is always better than an array because insertion is O(1). Give the two-part correction.

    show answer

    One: reaching the position costs O(n) unless you already hold the predecessor, so insertion into a list is only O(1) at a known position. Two: access and memory density are worse, measured here as 32 bytes per node against 4 bytes per array element, and 12.6x slower per element in a walk.

  8. Define an abstract data type and explain why "stack" is one while "array" is not.

    show answer

    An ADT is the logical specification of data plus operations plus the rules they obey, with the implementation hidden. A stack is an ADT because it is fully described by push, pop, top and LIFO order, and can be implemented by an array or by nodes. An array is a concrete memory layout, not a contract: it fixes the storage in its definition.
