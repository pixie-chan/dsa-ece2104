=== 14. the one line to remember ===
  bubble moves neighbours and stops early, selection always scans the whole tail,
  insertion shifts only what the new element must pass. All three are O(n^2) in the
  average case, only bubble and insertion get an O(n) best case, and only insertion
  is the one you actually use for small or nearly sorted data.

=== 11. the one line to remember ===
  split in half, sort each half, merge the two sorted halves in one linear pass. The
  recursion tree is log2(n) deep no matter what the input looks like, so the cost is
  ~n log2 n comparisons in every case, and the price is an n element buffer. On a
  linked list the buffer disappears because merging relinks nodes instead of copying.

  variant           best        average     worst case   stable   space     worst input measured at n = 1024

  every worst case in that column is O(n^2): the split is decided by the data, so no
  pivot rule removes the bad case, it only decides which inputs reach it. Median-of-three
  does not change the theoretical bound, and an adversary who knows the pivot rule can
  still force the quadratic case. What the measured column shows is which of the four
  teaching inputs each choice survives: at n = 1024 the quadratic form is 523776 comparisons and a healthy run stays near n log2 n = 10240
  read the measured column against those two numbers: sorted   is where lomuto-last collapses (523776), all-equal is where lomuto-median3 collapses (525822), hoare-first collapses on sorted
  and reverse (526334), and hoare-median3 never left the healthy band on any of
  the four shapes, which is a statement about these inputs, not a proof about all inputs
  quick sort is NOT stable: a partition swaps elements across the whole range, so equal
  keys change order, and none of the four variants repairs that. The cure for stability is
  the merge sort of lesson 17 or a sort by (key, original index) pairs
  quick sort sorts in place: every run in this lesson moved 2949120 bytes in 27 allocations, all of them this lesson's own scratch copies

=== 13. the one line to remember ===
  pick a pivot, move everything smaller to its left and everything larger to its right,
  then do it again on both sides. The partition is one linear pass, so the cost is the
  depth of the recursion: log2(n) levels when the pivot splits the range evenly,
  n levels when it does not. Median-of-three makes the even split the normal case, and
  Hoare's crossing pointers survive the all-equal input that kills Lomuto.
